# Cortex

A knowledge service that exposes retrieval and ingestion APIs over **OKF bundles**.
Cortex contains no LLM agent: it provides structured tools for external agentic
systems to query, navigate, and ingest knowledge.

- OKF (Open Knowledge Format) 0.2 bundles: markdown files with YAML frontmatter.
- **Multi-bundle**: a `bundles` directory whose subdirectories are bundles, each
  named by its folder. New bundles are discovered automatically on ingest.
- Files-first retrieval: search returns **concept pointers**; content is read
  from the bundle so answers stay grounded in source markdown.
- Config-switchable embedding providers: sentence-transformers (default), ollama,
  Vertex AI.

## Quick start

```bash
uv sync --extra embeddings
CORTEX_BUNDLES_ROOT=examples/bundles uv run cortex
```

This serves two example bundles, `retail` and `platform`. Hit the API on
`http://localhost:8000`, or browse the interactive docs at
`http://localhost:8000/docs`.

## API

| Method | Path                    | Description                                          |
| ------ | ----------------------- | ---------------------------------------------------- |
| POST   | `/ingest`               | Rescan bundles; embed concepts; regenerate `index.md`. |
| POST   | `/search`               | Search in `vector`, `lexical`, or `hybrid` mode.     |
| GET    | `/concepts/{path}`      | Full concept body from the bundle; directories fall back to a listing. |
| GET    | `/index/{dir}`          | Directory listing with the generated `index.md` content. |

Concept paths are **bundle-qualified**: the first segment names the bundle and
the rest is the path within it, e.g. `retail/tables/orders`.

### Ingest

```bash
curl -X POST http://localhost:8000/ingest -H 'Content-Type: application/json' -d '{"bundle": "retail", "path": "tables"}'
```

```json
{"indexed": 2, "updated": 0, "deleted": 1, "index_files": 1, "errors": []}
```

Both fields are optional: omit `path` to rescan a whole bundle, omit `bundle`
to rescan every bundle. Malformed concepts are skipped and reported in `errors`;
the rest still index. Referencing an unknown bundle name is a 404.

### Search

```bash
curl -X POST http://localhost:8000/search -H 'Content-Type: application/json' \
  -d '{"query": "revenue", "mode": "hybrid", "top_k": 5, "bundle": "retail", "type": "guide"}'
```

Search runs across all bundles by default; `bundle` narrows to one. It returns
pointers, not answers:

```json
[
  {
    "bundle": "retail",
    "concept_path": "retail/guides/revenue",
    "type": "guide",
    "title": "Revenue guide",
    "description": "How revenue is derived from orders.",
    "snippet": "Revenue is the sum of approved orders.total_cents...",
    "score": 0.87
  }
]
```

Read the full source concept with `GET /concepts/retail/guides/revenue`.

## Managing an OKF bundle

### Bundles root

All indexed bundles live under a single root folder (`CORTEX_BUNDLES_ROOT`,
default `bundles`). Each immediate subdirectory is one bundle, named by its
folder:

```
bundles/                          <- the bundles root (CORTEX_BUNDLES_ROOT)
├── retail/
│   ├── home.md
│   ├── glossary.md
│   ├── tables/
│   │   ├── orders.md
│   │   └── customers.md
│   └── guides/
│       └── revenue.md
└── platform/
    ├── deploy.md
    └── compute/
        └── regions.md
```

`index.md` files in the tree are generated by Cortex on ingest — you do not
maintain them. Add, edit, or remove concepts with your editor or tooling of
choice, then trigger `POST /ingest` to sync the index.

### Add a bundle

Create a directory under the bundles root and drop concepts in it. It is picked
up automatically on the next ingest — no config change needed.

### Add a concept

```markdown
---
type: reference
title: Orders table
description: Columns and semantics of the orders table.
tags: [tables, sql]
---

The `orders` table records every customer purchase.
```

```bash
curl -X POST http://localhost:8000/ingest -H 'Content-Type: application/json' -d '{"bundle": "retail"}'
```

### Update a concept

Edit the file in place (frontmatter + body), then re-ingest. Changed concepts
are re-embedded and counted in `updated`; their Chroma entries are replaced.

### Delete a concept

Remove the `.md` file and re-ingest. Cortex treats Chroma as the source of truth
for what was indexed: concepts that disappeared from the bundle since the last
ingest are removed from the index (`deleted`) and dropped from `index.md`.

### index.md

Cortex reserves `index.md` as a progressive-disclosure listing at each level of
the bundle. You never maintain these by hand: `POST /ingest` regenerates them
for every affected directory.

## Configuration

All settings come from environment variables prefixed with `CORTEX_`
(see `cortex/settings.py`).

| Variable                    | Default                    | Purpose                              |
| --------------------------- | -------------------------- | ------------------------------------ |
| `CORTEX_BUNDLES_ROOT`       | `bundles`                  | Directory whose subdirectories are bundles. |
| `CORTEX_CHROMA_PATH`        | `.cortex/chroma`           | Chroma persist directory.            |
| `CORTEX_CHROMA_COLLECTION`  | `concepts`                 | Chroma collection name.              |
| `CORTEX_EMBEDDING_PROVIDER` | `sentence-transformers`    | `sentence-transformers`, `ollama`, or `vertex`. |
| `CORTEX_OLLAMA_BASE_URL`    | `http://localhost:11434`   | Ollama endpoint.                     |
| `CORTEX_OLLAMA_EMBEDDING_MODEL` | `nomic-embed-text`     | Ollama embedding model.              |
| `CORTEX_VERTEX_PROJECT`     | —                          | GCP project for Vertex AI.           |
| `CORTEX_VERTEX_LOCATION`    | `us-central1`              | Vertex AI region.                    |
| `CORTEX_VERTEX_EMBEDDING_MODEL` | `text-embedding-005`   | Vertex embedding model.              |

The `ollama` and `vertex` providers live behind `uv sync --extra embeddings`.

## Development

```bash
uv sync --group dev
uv run pytest
uv run ruff check src tests
```

The test suite runs against the example bundles with a stub embedding provider,
so no model download or API keys are needed.
